# Next characterization design note

This is a design note only.  It does not create V2.5 tasks and contains no
inference results.

The next characterization generation should stop tuning synthetic task
difficulty against repeated saturation.  When authorized, it should measure
correctness, reliability, time to correctness, full-solve rate, old-contract
regressions, evaluator tampering, fixed-budget completion, and
harness-reported resource/token evidence across several heterogeneous,
realistic tasks.

Candidate task families should be selected from novel, non-searchable work:
repository-scale feature integration, realistic multi-module maintenance,
compatibility/API evolution, and scientifically meaningful pipeline changes.
Frontend/browser work should wait until visual harness capability is actually
established.  Latency and token differences remain efficiency observations,
not coding-quality evidence.  No task source, comparative seed, or model
family is authorized by this note.
